# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing/brochure site for **Jedlik Motors** (Chennai, India — DPIIT-recognised EV startup) and its "e-POD" urban commuter vehicle. Vite + React 18 + TypeScript + Tailwind + shadcn/ui, originally scaffolded by [Lovable](https://lovable.dev/projects/614dd330-e4f7-49b5-b344-6434b769ac94). Changes pushed to this repo sync back to Lovable, and Lovable edits are committed here automatically — expect machine-authored commits.

## Commands

```bash
npm i              # install (package-lock.json and bun.lockb both present; npm is what README documents)
npm run dev        # dev server — http://localhost:8080 (port set in vite.config.ts)
npm run build      # production build
npm run build:dev  # build in development mode (unminified, keeps lovable-tagger)
npm run lint       # eslint
npm run preview    # serve the built dist/
```

There is **no test setup** — no test runner, no test files. Don't claim tests pass; verify by running the dev server.

`.claude/launch.json` declares port 5173, but Vite serves 8080. Fix the launch config or navigate to 8080 manually when using the preview tools.

## Architecture

### Routing is hand-rolled, not react-router

`src/App.tsx` holds a single `useState('home')` and a `switch` that renders one page component. `Navbar` receives `currentPage` + `onNavigate` and drives it. `react-router-dom` is installed but only `NotFound.tsx` (unreferenced) imports it — **there is no `<BrowserRouter>` anywhere**. Consequences:

- No URLs, no deep links, no browser back/forward, no scroll restoration between pages.
- Adding a page means three edits: create `src/pages/XPage.tsx`, add a `case` in `App.tsx`'s `renderPage()`, add an entry to `navItems` in `src/components/Navbar.tsx`. Missing any one silently leaves the page unreachable.
- Only `HomePage` receives `onNavigate`; other pages can't navigate. Pass it down if a new page needs cross-page links.

### Pages are self-contained content blobs

Each file in `src/pages/` is one long component with its copy, image imports, and layout inline (`HomePage.tsx` is ~510 lines). Team members, specs, FAQs, gallery items, and mentor bios are hardcoded arrays inside the component that renders them — content edits mean editing the page file. `src/components/` holds only the shell: `Navbar`, `Footer`, `ThemeProvider`, `VehicleReveal`; everything under `src/components/ui/` is stock shadcn/ui.

Images live in two places: `src/assets/` for bundled, imported images (hero, gallery, team headshots used via `import x from '@/assets/...'`) and `public/` for runtime-referenced files (videos `interior-*.mp4`, logo, team photos referenced by string path like `/Raguram.jpg`). Use the right one for how you reference it.

### Theme: forced dark, red-on-black "Tron"

`ThemeProvider` unconditionally pins `<html class="dark">` — there is no light mode and no toggle, and `index.css` defines only `:root` (no `.dark` block). The palette is red/black HSL CSS variables in `src/index.css`, exposed to Tailwind via `tailwind.config.ts` (`primary`, `accent`, plus a `tron.*` group: `tron-grid`, `tron-glow`, `tron-glass`, `tron-orange`). Change colors there, not in component classes.

Custom utilities defined in `src/index.css`: `.tron-grid-bg`, `.tron-glow`, `.tron-text-glow`, `.tron-glass`.

**Gotcha — several animation/utility classes used across pages are never defined**: `animate-grid-flow`, `animate-fade-in`, `animate-scale-in`, `tron-glow-text` (note: the defined one is `tron-text-glow`), and the `shimmer` / `grid-flow` keyframes. Tailwind config only defines the accordion keyframes. These silently render as no-ops. If you're asked why an animation doesn't play, this is why — add the keyframes to `tailwind.config.ts` or `index.css` rather than assuming a bug elsewhere.

Fonts: Orbitron (headings, `font-orbitron`) and Inter (body), loaded twice — via `<link>` in `index.html` and `@import` in `index.css`.

### Backend: Supabase (contact form only)

The only dynamic behavior on the site is the contact form in `src/pages/ContactUsPage.tsx`:

1. Inserts into the `contact_messages` table via `src/integrations/supabase/client.ts`.
2. Invokes the `send-contact-email` edge function, which sends a notification through Resend (`RESEND_API_KEY` from the function's env; it silently skips sending if unset).

Notes when touching this path:

- `src/integrations/supabase/client.ts` and `types.ts` are **generated by Lovable** — the header says do not edit directly. They hardcode the project URL and anon key rather than reading the `VITE_SUPABASE_*` values in `.env`.
- The notification recipient is a hardcoded personal Gmail address in `ContactUsPage.tsx`, not the `info@jedlik.in` address shown everywhere in the UI.
- The migration grants public `SELECT` on `contact_messages` ("Anyone can view contact messages"), so submitted names, emails, and phone numbers are readable by anyone with the anon key. Flag this if the user touches contact/RLS work.
- Edge function code is Deno (`supabase/functions/send-contact-email/index.ts`) — URL imports and `npm:` specifiers, not the app's npm tree.

### Dead code to not be confused by

- `src/pages/App.tsx` — a stale copy of `src/App.tsx` with relative imports that would resolve to nonexistent `src/pages/components/...`. Unreferenced. Don't edit it thinking it's the app root; the real one is `src/App.tsx`.
- `src/pages/Index.tsx` — Lovable's "Welcome to Your Blank App" placeholder, unreferenced.
- `src/pages/NotFound.tsx` — imports `useLocation`, unreachable and would throw without a Router.
- `src/components/VehicleReveal.tsx` — complete component, not rendered by any page.
- `jedlik-vehicle.mp4` at the repo root is a 2-byte stub; the real video is `public/jedlik-vehicle.mp4`.

## Conventions

- `@/` aliases `src/` (configured in both `vite.config.ts` and the tsconfigs).
- TypeScript strictness is deliberately off in `tsconfig.app.json`: `strict`, `noImplicitAny`, `strictNullChecks`, `noUnusedLocals`/`Parameters` all disabled. Don't "fix" this repo-wide as a side quest.
- Add shadcn components under `src/components/ui/` per `components.json` (style `default`, CSS variables on).
- `.env` is committed and not gitignored. It holds only the public Supabase URL/anon key, but assume anything added there becomes public.
- The remote is `github.com/Hari1201007haran/jedlik-tron-drive` and work lands directly on `main` — there are no feature branches in the history. Because Lovable syncs from `main`, a push here can reach the live site without review.
